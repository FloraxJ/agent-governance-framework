# Чистота репозитория и защита от шума тяжелых движков (Unity / Unreal)

В репозиториях игровых движков параллельно с агентом часто работает разработчик в редакторе (Unity Editor / Unreal Editor). Это приводит к фоновой модификации сотен ассетов, метафайлов и настроек.

---

## 1. Поимённое добавление в Git (Strict Named Staging)
- **Категорический запрет группового добавления:**
  `git add .`, `git add -A` и `git commit -a` **строго запрещены**.
- **Только явные пути:** Файлы добавляются исключительно поштучно: `git add path/to/file.cs`.
- *Обоснование:* Групповой коммит гарантированно затянет чужие локальные `.asset`, `.prefab`, `.unity`, сгенерированные шейдеры или временные настройки редактора.

---

## 2. Защита встроенных пакетов (Embedded Packages) и патчей
- Если в проект встроен форк сторонней библиотеки с критическими патчами:
  1. Запрещено обновлять или подключать этот пакет через публичные менеджеры пакетов (UPM, NuGet, Cargo), так как это перезапишет локальные изменения версией из кэша;
  2. Все внутренние правки обязаны маркироваться стандартизированным комментарием (например: `// CUSTOM-PATCH: <причина>`).

---

## 3. Откат шума редактора и batchmode-прогонов
- Любой запуск движка в headless/batchmode перезаписывает сериализованные ассеты и глобальные настройки.
- После каждого тестового прогона или билда агент обязан:
  1. Проверить статус репозитория: `git status`;
  2. Откатить всё, что не относится к текущей задаче: `git checkout -- <файлы_ассетов>`.
- Локальные автогенерируемые файлы (настройки аналитики, временные тестовые сцены, кэши) должны быть вычищены до создания Pull/Merge Request.
