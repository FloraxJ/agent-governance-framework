# Гигиена Git Worktrees и дискового пространства

В проектах с тяжелыми бинарными кэшами (Unity `Library`, Unreal `Intermediate` / `Saved`) каждая рабочая копия репозитория (`git worktree`) может весить **15–30+ ГБ**. Бесконтрольное создание веток агентами моментально переполняет диск.

---

## 1. Запрет стихийного создания рабочих копий
- Запрещено создавать новые worktrees без предварительного анализа дискового пространства и согласования.
- Предпочтительно переиспользовать постоянные выделенные изолированные деревья (например, отдельное дерево под playmode-тесты, отдельное под билд-раннеры).

---

## 2. Комплексный протокол «Дерево свободно»
Чистого вывода `git status` и отсутствия запущенных процессов движка **недостаточно** (параллельные сессии других разработчиков или фоновые раннеры могут работать с файлами по абсолютным путям).

Перед переключением ветки (`git switch`) в существующем дереве агент обязан проверить:
1. **Свежая активность файлов:**
   `find <worktree_path> -maxdepth 3 -mmin -120 -type f` (исключая системные кэши Library/Intermediate);
2. **Наличие незавершённой работы:** `git stash list`;
3. **Время последнего коммита:** `git log -1 --format=%cr`.
*Если за последние 2 часа была активность — переключение запрещено без подтверждения человека.*

---

## 3. Обязательная уборка временных деревьев
Любой временный worktree, созданный для изолированного замера или снятия профиля, должен быть удален (`git worktree remove`) сразу после формирования артефакта или отправки изменений.
